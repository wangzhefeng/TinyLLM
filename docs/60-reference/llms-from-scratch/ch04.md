### 3.4 Chapter 4：Implementing a GPT Model

**主线内容**

- GPT 配置（124M：emb 768、12 层、12 头、ctx 1024、vocab 50257）。
- LayerNorm、GELU、FeedForward（4× 扩展）、TransformerBlock、残差连接、最终 norm、输出头。
- 文本生成：greedy、temperature、top-k；`generate_text_simple`。
- 参数量与 FLOPs 的估算。

**Bonus：注意力与效率的“专题库”**

| 子目录 | 内容 | 关键点 |
|---|---|---|
| `02_performance-analysis` | FLOPs/参数量分析 | 用公式与脚本估算计算量 |
| `03_kv-cache` | KV cache：naive / optimized | 预分配 + 滑动窗口截断；生成结果必须与无 cache 完全一致 |
| `04_gqa` | Grouped-Query Attention | KV head 分组，KV cache 显存估算 |
| `05_mla` | Multi-Head Latent Attention | 将 K/V 压缩到低维 latent，DeepSeek V2/V3 的核心 |
| `06_swa` | Sliding Window Attention | 局部窗口，Gemma 2/3 的 5:1 局部/全局混合 |
| `07_moe` | Mixture-of-Experts | router、top-k、负载均衡、专家 FFN |
| `08_deltanet` | Gated DeltaNet | 线性注意力/RNN 式状态更新，Qwen3-Next、Kimi Linear |
| `09_dsa` | DeepSeek Sparse Attention | Lightning Indexer + top-k token 选择 |
| `10_kv-sharing` | Cross-layer KV sharing | 后层复用前层 K/V，Gemma 4 E2B/E4B |

**对本项目**：

- ✅ GPT-2 模型、生成、KV cache（含 optimized/batched/streaming）、GQA、MoE、FLOPs 分析都有。
- 🟡 SWA 只在 `models/gemma3/Gemma3_270M.py` 的 local/global mask 中体现，没有独立实现与显存估算。
- ❌ MLA 只有 `layers/attention.py` 里的空类 `MultiHeadLatentAttention`（`pass`），`models/deepseek/model.py` 也是空壳。
- ❌ DeltaNet、DSA、跨层 KV 共享完全没有。

> 这 5 个空白正好对应 2025–2026 年最主流的架构演进方向，建议作为“架构补课”的第一优先级。
