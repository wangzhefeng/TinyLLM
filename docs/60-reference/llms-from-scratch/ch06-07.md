### 3.6 Chapter 6：Finetuning for Classification

**主线内容**

- SMS Spam Collection 数据集：下载、类别平衡、train/val/test 划分。
- 文本 padding、分类头、取最后一个 token 的 logits。
- 冻结模型、只训练最后一个 block + 分类头；对比全量微调。
- 训练/验证/测试准确率、混淆矩阵、UI。

**Bonus**

| 子目录 | 内容 |
|---|---|
| `02_bonus_additional-experiments` | 19 组对照：first token vs last token、只训最后一层/最后两块/全部、LoRA、不同模型规模、context 长度、padding 策略、是否 causal mask、`ignore_index`、pooled embedding |
| `03_bonus_imdb-classification` | 50k IMDb 影评，对比 GPT-2 124M、BERT、DistilBERT、RoBERTa、DeBERTa-v3、ModernBERT、逻辑回归 |
| `04_user_interface` | 分类模型的 Streamlit UI |

**对本项目**：

- ❌ 没有 GPT-2 分类微调闭环。`utils/calc_loss.py` 里有 `task_name == "clf_sft"` 的分支，说明设计上预留了分类任务，但没有数据管线、训练入口与实验类。
- 🟡 有一个“从零 BERT”实现（`models/bert/model.py`，训练入口 `run_bert.py`）和 HF BERT 情感分类尝试（`post_training/sft/bert_sentiment/`），但 `bert_sentiment/run.py` 是空壳；数据集是 THUCNews，不是 SMS/IMDb。
- ❌ 没有 ch06 的 19 组对照实验、IMDb baseline 对比、分类 UI。

> 这是“投入小、收益大”的缺口：复用现有 GPT-2 权重与训练框架，1–2 天可以补出 SMS 分类闭环，并顺带修复 `calc_loss` 的 `clf_sft` 分支。

### 3.7 Chapter 7：Finetuning to Follow Instructions

**主线内容**

- 指令数据格式：`instruction` / `input` / `output`。
- Prompt 模板（"Below is an instruction..."）+ `### Response:`。
- `InstructionDataset`：把 instruction+input+output 拼成一条序列。
- `custom_collate_fn`：padding、target 右移、`ignore_index=-100`；主章节只 mask padding，**mask 掉 instruction token 是习题扩展**。
- 在 1100 条 Alpaca 风格数据上做 SFT，观察 loss 与生成质量。
- 用 Ollama/OpenAI 对回答打分。

**Bonus**

| 子目录 | 内容 |
|---|---|
| `02_dataset-utilities` | 近重复检测（`find-near-duplicates.py`）、主动/被动语态数据构造 |
| `03_model-evaluation` | 用 GPT-4 API 或本地 Ollama Llama 3 给指令回答打分 |
| `04_preference-tuning-with-dpo` | 构造偏好数据 + 从零实现 DPO loss + 训练 + 结果分析 |
| `05_dataset-generation` | 用 Llama 3 + Ollama 合成指令数据；用 GPT-4 做 reflection 式数据改进 |
| `06_user_interface` | 指令微调模型的 Streamlit UI |

**对本项目**：

- ❌ 没有 SFT 训练闭环。`test/llmbox/data_provider/sft_dataset/` 有 Alpaca/Dolly/LIMA/ShareGPT 等数据适配器，`test/minimind/data_provider/data_loader.py` 有 `SFTDataset`/`DPODataset`，但都没有接到训练入口；`test/minimind/scripts/*.sh` 引用的 `3-full_sft.py`、`full_sft.py` 并不存在。
- ❌ DPO 只有数据 loader，没有 DPO loss、reference model、训练循环。
- ❌ 数据集工具缺失：`scripts/find_near_duplicates.sh` 指向的 `data_provider/finetune/instruction_follow/find_near_duplicates.py` 不存在。
- 🟡 评测：`qwen3_reasoning/evaluation/benchmark_based_eval/math_verifiers.py`（438 行）与 `multiple_choice.py`（135 行）是真实实现；`llm_leaderboards.py` 有实现但依赖缺失，`llm_judges*.py`、`elo_leaderboard.py`、`bradley_terry_leaderboard.py` 仍是空壳。（历史路径，现已上提 `evaluation/` 公共库并补齐：`evaluation/verifiers/`、`evaluation/judges/`）
- ❌ 合成数据生成（Ollama/OpenAI/reflection）没有。
- ❌ 指令微调 UI 没有（现有 `apps/` 只做预训练模型对话）。

> 这是当前最大的内容缺口，也是“从会预训练到会做产品级 LLM”的关键一跃。
